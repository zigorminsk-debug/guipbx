# ☎ GUIPBX — визуальный конструктор сценариев Asterisk

Веб-редактор блочного типа (в духе редактора сценариев **Oktell**): администратор **рисует карту прохождения вызова** — от точки входа до конечной точки, с ветвлениями, исходящими маршрутами и переадресациями. Нарисованная карта **компилируется в рабочий диалплан Asterisk** и выгружается на станцию прямо из браузера. Существующие настройки станции, наоборот, можно **прочитать и увидеть схемой**.

Бэкенд — **единый бинарник на Go** (стандартная библиотека, без внешних зависимостей): веб-интерфейс встроен через `embed`, состояние — JSON-файлы в `data/`. Node.js нужен только для dev-инструментов (фолбэк-сервер и smoke-тесты).

## Возможности

- **Полигон монтажа** — холст с зумом, панорамой, сеткой, drag&drop блоков, соединением портов «проводами».
- **Палитра из 23 блоков**: точки входа (входящий DID / исходящий шаблон), действия (ответ, голосовые сообщения, IVR-меню, запись разговора, пауза, CallerID, переменная, HTTP-запрос, лог), логика (условие времени, произвольное условие), назначения (абонент, группа, очередь, конференция, голосовая почта, переадресация, транк, парковка, «занято», завершение) и блок «Своя команда» для произвольных приложений Asterisk (AGI, Gosub, DISA…).
- **Реестр устройств и транков** — SIP-абоненты и SIP-транки; при компиляции генерируется `pjsip.conf` (+`queues.conf` для очередей).
- **Компиляция карты** в `extensions.conf`: именованные приоритеты, цифровые extension-ы IVR, `GotoIfTime`, `GotoIf`, разрешение ветвлений.
- **Проверка схемы** — предупреждения: неподключённые выходы, отсутствие точки входа, незаданные устройства/транки.
- **🖧 Подключение к станции (AMI)** — по IP, логину и паролю администратора:
  - **⬇ Прочитать настройки со станции** — выполняется `dialplan show`, выбранные контексты разбираются и **рисуются блок-схемами** (с авто-раскладкой); неизвестные приложения становятся блоками «Своя команда».
  - **💾 На станцию + reload** — карта компилируется, контекст станции очищается и наполняется заново через `dialplan add extension …` (CLI не умеет именованные приоритеты — метки разрешаются в числа), затем `dialplan reload`. Для контекстов не-GUIPBX (импортированных) требуется подтверждение перезаписи.
  - **⌨ Произвольная CLI-команда** из браузера.
- **Вывод в работу без AMI** — запись `extensions_gui.conf` на диск хоста или скачивание файла.
- **Автосборка**: GitHub Actions собирает и проверяет каждый push (см. ниже).

## Запуск

```bash
go build -o guipbx .
./guipbx                 # http://localhost:3000
PORT=8080 ./guipbx       # другой порт
```

Готовые бинарники под Linux (amd64/arm64), Windows и macOS забирайте из артефактов CI или пререлиза **nightly** (собирается с каждого push в `main`).

При первом запуске создаются две демо-схемы («Входящий вызов» с IVR и «Исходящий маршрут») и реестр с абонентами 100/101 и транком `provider`. Данные — в `data/` (не коммитится).

### Dev-режим на Node (необязательно)

```bash
npm install
npm run dev            # фолбэк-сервер без AMI (заглушки 501), для разработки UI
npm run selftest       # самопроверка JS-компилятора
node scripts/ui-smoke.js http://localhost:3000   # UI-смоук против запущенного сервера
```

## Подключение к станции Asterisk

1. Нажмите **🖧 Станция**, введите **IP, логин и пароль администратора** (AMI из `/etc/asterisk/manager.conf`):
   ```
   [admin]
   secret = TopSecret
   permit = 0.0.0.0/0.0.0.0
   read = command
   write = command
   ```
2. **⬇ Прочитать настройки**: отметьте контексты (свои `gui-*` уже отмечены) — они появятся в списке схем с авто-раскладкой. Схема помнит исходное имя контекста станции.
3. Отредактируйте карту, нажмите **🚀 В работу → 💾 На станцию + reload**: выгрузка сначала валидируется, импортированные контексты требуют подтверждения (без `force` чужие контексты не перезаписываются).

Круговая согласованность «схема → диалплан → станция → схема» покрыта тестом `TestRoundTrip` (см. `astdump_test.go`).

## Как это работает

1. Блок «Входящий вызов» задаёт DID; «Исходящий маршрут» — шаблон набора (`_89XXX…`).
2. Провода рисуют цепочку действий; IVR и условия дают несколько выходов.
3. **⚙ Компилировать** превращает граф в `[gui-<id>-in-N]` / `[gui-<id>-out-N]`; исходящие контексты автоматически включаются в `[gui-internal]`.
4. **🚀 В работу** — выгрузка на станцию (AMI) или в файл.

## CI (автосборка на GitHub Actions)

Workflow `.github/workflows/ci.yml` запускается на каждый push и pull request:

| Джоба | Что делает |
|---|---|
| **Go · gofmt + vet + тесты** | `go vet`, `go test -v ./...` (компилятор, CLI-выгрузка, AMI на фейковой станции, парсер `dialplan show`, круговой тест); при падении лог публикуется в issue |
| **Web UI · smoke** | сборка бинарника, запуск, `selftest` компилятора и `ui-smoke` (в браузерном DOM: тулбар, палитра, модалки, форма подключения к станции, обработка ошибок) |
| **Бинарники ×5** | linux/amd64, linux/arm64, windows/amd64, darwin/amd64, darwin/arm64 + sha256 → артефакты |
| **Релиз nightly** | при push в `main`: пререлиз `nightly` со всеми бинарниками |

## Структура

```
main.go        — HTTP-сервер: REST API, embed-статика, станция (connect/import/push/CLI)
storage.go     — схемы и реестр: JSON-файлы в data/
seeds.go       — демо-данные первого запуска
dialplan.go    — компилятор графа → extensions.conf / pjsip.conf / queues.conf
cliplan.go     — диалплан → команды CLI (разрешение меток в числовые приоритеты)
ami.go         — AMI-клиент (Login → Command → Logoff) без зависимостей
astdump.go     — парсер «dialplan show» → блок-схема (обратное преобразование)
*_test.go      — модульные тесты: компилятор, CLI, AMI (фейк-станция), импорт, round-trip
public/        — веб-интерфейс: index.html, css/, js/{blocks,graph,app}.js
server/        — dev-фолбэк на Node: REST API + тот же компилятор на JS
scripts/       — selftest.js (компилятор), ui-smoke.js (DOM-прогон интерфейса)
.github/workflows/ci.yml — автосборка
```

## API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| GET/POST | `/api/schemes` | список / создание схемы |
| GET/PUT/DELETE | `/api/schemes/{id}` | чтение / сохранение / удаление |
| GET | `/api/schemes/{id}/compile` | компиляция схемы (+ предупреждения) |
| GET | `/api/project/compile`, `/api/project/download` | весь проект |
| GET/PUT | `/api/registry` | устройства и транки |
| POST | `/api/deploy` | запись `extensions_gui.conf` на диск хоста |
| POST | `/api/station/connect`, `/disconnect` | сессия AMI по IP/логину/паролю |
| GET | `/api/station/status` | состояние подключения |
| GET | `/api/station/contexts` | список контекстов станции (`dialplan show`) |
| GET | `/api/station/dialplan-raw` | сырой текст диалплана станции |
| POST | `/api/station/import` | контексты станции → схемы GUIPBX |
| POST | `/api/station/push` | схема → станция (+`dialplan reload`), `force` для чужих контекстов |
| POST | `/api/station/command` | произвольная CLI-команда на станции |
