# ☎ GUIPBX — визуальный конструктор сценариев Asterisk

Веб-редактор блочного типа (в духе редактора сценариев **Oktell**): администратор **рисует карту прохождения вызова** на полигоне монтажа — от точки входа до конечной точки, с ветвлениями, исходящими маршрутами и переадресациями. Нарисованная карта **компилируется в рабочий диалплан Asterisk** и выводится в эксплуатацию одной кнопкой.

![Тип работы](https://img.shields.io/badge/type-visual--pbx-blue)

## Возможности

- **Полигон монтажа** — холст с зумом, панорамой, сеткой, drag&drop блоков, соединением портов «проводами», автоизгибами безье и стрелками направления.
- **Палитра инструментов:**
  - *Точки входа:* «Входящий вызов» (DID/шаблон), «Исходящий маршрут» (шаблон набора).
  - *Действия:* Ответить, Воспроизвести, IVR-меню (клавиши 0–9/*/# + таймаут/ошибка), Запись разговора (MixMonitor), Пауза, Изменить CallerID, Переменная, HTTP-запрос (CURL), Лог-метка.
  - *Логика:* Условие времени (рабочие часы), произвольное условие Asterisk.
  - *Устройства и назначения:* Вызов абонента, Группа вызова (параллельно/по очереди), Очередь, Конференция, Голосовая почта, **Переадресация на внешний номер**, «Внешний номер (транк)», Парковка, «Занято», Завершить вызов.
- **Реестр устройств и транков** — SIP-абоненты с автогенерацией паролей, SIP-транки с регистрацией/идентификацией; генерируется `pjsip.conf`.
- **Компиляция карты** в `extensions.conf` (`same => n(...)`, именованные приоритеты, цифровые extension-ы IVR, `GotoIfTime`, `GotoIf`), плюс `queues.conf` для очередей.
- **Проверка схемы** — предупреждения: неподключённые выходы, недостижимые блоки, отсутствие точки входа, незаданные устройства/транки.
- **Вывод в работу** — запись `extensions_gui.conf` на Asterisk-хост + перезагрузка диалплана через **AMI**. Либо скачивание `.conf` и ручное подключение.
- Автосохранение, Undo/Redo (Ctrl+Z/Y), дублирование блоков (Ctrl+D), слияние ветвей.

## Запуск

```bash
npm install
npm start          # http://localhost:3000
# или
PORT=8080 node server/index.js
```

При первом запуске создаются две **демо-схемы** («Входящий вызов» с IVR и «Исходящий маршрут») и реестр с абонентами 100/101 и транком `provider`. Данные хранятся в `data/` (не коммитится).

## Как это работает

1. На полигоне блок «Входящий вызов» задаёт DID (`s`, точный номер или шаблон `_7495XXXXXXX`).
2. Провода рисуют цепочку действий; IVR и условия дают несколько выходов — каждый выход ведёт свою ветку.
3. Кнопка **⚙ Компилировать** превращает граф в контекст `[gui-<id>-in-N]` / `[gui-<id>-out-N]`.
4. Кнопка **🚀 В работу** пишет `extensions_gui.conf` и делает `dialplan reload` по AMI — карта начинает принимать вызовы.

## Подключение к боевому Asterisk

1. Скопируйте `extensions_gui.conf` (кнопка **⬇ .conf** или «В работу») в `/etc/asterisk/`.
2. В `/etc/asterisk/extensions.conf` добавьте:
   ```
   #include "extensions_gui.conf"
   ```
3. Сгенерированный `pjsip.conf` (вкладка компиляции) подключите аналогично в `/etc/asterisk/pjsip.conf`:
   ```
   #include "pjsip_gui.conf"
   ```
4. Входящие звонки попадут на карту, если у транка в `pjsip.conf` стоит `context=gui-<id схемы>-in-1` (подсказка показывается в свойствах блока «Входящий вызов»; у сидового транка `provider` уже проставлено).
5. Исходящие маршруты автоматически включаются в `[gui-internal]` — внутренним абонентам достаточно этого контекста.
6. Для кнопки «dialplan reload» включите AMI в `/etc/asterisk/manager.conf`:
   ```
   [admin]
   secret = TopSecret
   read = command
   write = command
   ```
   Параметры подключения укажите в GUI: **🔌 Asterisk**.

## Структура

```
server/
  index.js      — Express: REST API, хранение схем/реестра, деплой, AMI-прокси
  dialplan.js   — компилятор графа → extensions.conf / pjsip.conf / queues.conf
  ami.js        — минимальный AMI-клиент (Login → Command → Logoff) без зависимостей
  seeds.js      — демонстрационные схемы и реестр первого запуска
public/
  index.html    — каркас UI (тулбар / палитра / полигон / свойства)
  js/blocks.js  — реестр блоков палитры (порты, поля, подсказки)
  js/graph.js   — движок полигона: зум, drag&drop, провода безье
  js/app.js     — логика приложения: схемы, свойства, компиляция, реестр, AMI
scripts/
  selftest.js   — самопроверка компилятора (npm run selftest)
```

## API (кратко)

| Метод | Путь | Назначение |
|---|---|---|
| GET/POST | `/api/schemes` | список / создание схемы |
| GET/PUT/DELETE | `/api/schemes/:id` | чтение / сохранение / удаление |
| GET | `/api/schemes/:id/compile` | компиляция одной схемы |
| GET | `/api/project/compile`, `/api/project/download` | весь проект |
| GET/PUT | `/api/registry` | устройства и транки |
| POST | `/api/deploy` | запись диалплана на диск хоста |
| POST | `/api/ami/test`, `/api/ami/reload` | проверка AMI / перезагрузка диалплана |
